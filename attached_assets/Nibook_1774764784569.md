\#\# 1\. What is Nibook?

Nibook is a \*\*SaaS booking platform for service professionals\*\* — hair stylists, coaches, nutritionists, photographers, consultants, and similar businesses. It is built for the African market (East Africa first: Kenya, Uganda, Tanzania) but designed to work globally.

A business owner signs up, sets up their profile, adds their services, and gets a \*\*public booking page\*\* they can share with clients. Clients pick a service, choose a date and time, enter their details, select a payment method, and book — no account required.

\#\#\# Core value proposition

| For the business owner | For their clients |  
|---|---|  
| Stop coordinating bookings over WhatsApp | Book in under 60 seconds |  
| Accept M-Pesa, bank, PayPal, or cash | See real-time availability |  
| Manage team members and roles | Get a professional, branded experience |  
| Track revenue and booking analytics | No sign-up required |

\#\# 3\. Architecture

\#\#\# Multi-tenant model

Every business is a \*\*workspace\*\*. All data is scoped to a workspace ID. A single user can own or belong to multiple workspaces.

\`\`\`  
profiles (1) ──\< workspace\_members \>── (N) workspaces  
                                            │  
                  ┌─────────────┬───────────┼───────────┬──────────────┐  
               services      bookings   availability  settings    subscriptions  
\`\`\`

\#\#\# Database tables (11)

| Table | Purpose |  
|---|---|  
| \`profiles\` | Clerk user identity (PK: \`clerk\_user\_id\`) |  
| \`workspaces\` | Business tenant — name, slug, category, logo |  
| \`workspace\_members\` | Many-to-many users↔workspaces with roles |  
| \`services\` | What the business offers (name, price, duration, images) |  
| \`bookings\` | Client appointments (date, time, status, payment) |  
| \`availability\` | Weekly schedule per day (on/off, start/end times) |  
| \`workspace\_settings\` | Theme, WhatsApp config, connections, payment methods, support |  
| \`invitations\` | Team invites with expiry (7 days) |  
| \`subscriptions\` | Plan (free/pro), status, billing cycle |  
| \`usage\_metrics\` | Services/bookings used vs limits |  
| \`payment\_orders\` | Jenga checkout transaction records |

\#\#\# Key files

| File | What it does |  
|---|---|  
| \`supabase/schema.sql\` | Full DDL — tables, indexes, triggers, RLS policies |

| \`src/hooks/use-public-booking.ts\` | Public (unauthenticated) data access for booking page |  
| \`src/hooks/use-account.ts\` | Profile \+ subscription \+ usage snapshot |

| \`src/lib/workspace-config.ts\` | Theme styles, config types |  
| \`src/lib/supabase.ts\` | Supabase client with Clerk JWT |  
| \`src/components/ServiceEditorDialog.tsx\` | Create/edit service with image upload |  
| \`src/components/RouteGuards.tsx\` | Onboarding redirect logic |

\#\# 6\. Known Gaps & Technical Debt

\#\#\# 6.1 Critical (blocks real-world usage)

| \# | Issue | Details |  
|---|---|---|  
| 1 | \*\*No email/SMS notifications\*\* | Booking confirmation, reminders, and cancellation emails are not implemented. Landing page promises them. |  
| 2 | \*\*WhatsApp integration is config-only\*\* | Settings page collects credentials, but no messages are actually sent. |  
| 3 | \*\*Connections are UI-only\*\* | Google Calendar, Slack, Zapier, MCP toggles exist but don't connect to anything. |  
| 4 | \*\*Booking rules not persisted\*\* | Buffer minutes, minimum notice, and max advance days are local state only — lost on refresh. |  
| 5 | \*\*No RLS policies verified in production\*\* | Schema defines \`enable row level security\` but policies need auditing for correct JWT claim matching. |  
| 6 | \*\*Usage limits not enforced\*\* | \`usage\_metrics\` table exists but nothing blocks a Free user from exceeding 3 services or 10 bookings. |  
| 7 | \*\*No Jenga webhook signature verification\*\* | \`jenga-callback\` should verify the callback is genuinely from Jenga. |

\#\#\# 6.2 Important (degrades experience)

| \# | Issue | Details |  
|---|---|---|  
| 8 | \*\*No analytics page\*\* | Dashboard shows basic stats, but there's no dedicated analytics view (promised in Pro). |  
| 9 | \*\*No search/filter on Services page\*\* | Works fine with few services, won't scale. |  
| 10 | \*\*No pagination\*\* | Bookings, services, and team pages fetch everything at once. |  
| 11 | \*\*Booking rules UI disconnected\*\* | Buffer, notice, and advance limits render but are never sent to the public booking page. |  
| 12 | \*\*No offline/error states\*\* | Failed Supabase queries show blank screens instead of error messages. |  
| 13 | \*\*No loading skeletons\*\* | Pages flash empty before data arrives. |  
| 14 | \*\*Calendar timezone handling\*\* | All dates are naive — no timezone awareness for international clients. |

\#\#\# 6.3 Nice to have

| \# | Issue | Details |  
|---|---|---|  
| 15 | \*\*No dark mode\*\* | \`next-themes\` is installed but not wired. |  
| 16 | \*\*No recurring bookings\*\* | Clients must book individually each time. |  
| 17 | \*\*No client login/portal\*\* | Clients can't view or manage their own bookings. |  
| 18 | \*\*No audit log\*\* | SAAS\_SETUP.md recommends audit logs but none exist. |  
| 19 | \*\*No i18n\*\* | All copy is English. Swahili/French would help target market. |  
| 20 | \*\*Service categories/tags\*\* | No grouping mechanism for businesses with many services. |

\#\# 7\. Roadmap

\#\#\# Phase 1 — Production Readiness

\*\*Goal:\*\* Make the app usable by a real business with paying clients.

| Task | Priority | Effort | Notes |  
|---|---|---|---|  
| Persist booking rules to \`workspace\_settings\` | High | Small | Add \`booking\_rules\` jsonb column, wire save/load |  
| Enforce usage limits server-side | High | Medium | Check limits in RLS policies or Edge Function before insert |  
| Add email notifications (booking confirm/cancel) | High | Medium | Use Resend, Postmark, or Supabase Edge \+ SMTP |  
| Verify & harden RLS policies | High | Medium | Test every table with anon/authenticated/wrong-user JWTs |  
| Add error boundaries & empty states | High | Small | Wrap pages in React error boundaries, show fallback UI |  
| Add loading skeletons | Medium | Small | shadcn/ui Skeleton on all data-dependent views |  
| Validate Jenga webhook signatures | High | Small | HMAC check in \`jenga-callback\` |  
| Add \`updated\_at\` trigger to \`workspace\_settings\` | Low | Tiny | Missing from current triggers |

\#\#\# Phase 2 — Core Integrations

\*\*Goal:\*\* Deliver on the integrations promised in marketing and settings UI.

| Task | Priority | Effort | Notes |  
|---|---|---|---|  
| WhatsApp booking confirmations | High | Large | Use Meta Cloud API or Twilio; creds already collected in settings |  
| Google Calendar sync | Medium | Large | OAuth flow, read/write events on booking create/cancel |  
| SMS reminders (day-before) | Medium | Medium | Africa's Talking or Twilio; cron via Supabase pg\_cron |  
| Zapier webhook | Low | Small | Fire webhook on booking events; Zapier handles the rest |

\#\#\# Phase 3 — Growth Features

\*\*Goal:\*\* Increase retention and upsell to Pro.

| Task | Priority | Effort | Notes |  
|---|---|---|---|  
| Analytics dashboard | High | Large | Bookings over time, revenue trends, top services, client retention |  
| Client portal (view/cancel own bookings) | Medium | Medium | Magic link or OTP login, scoped to client email |

\#\#\# Phase 4 — Scale & Monetize

\*\*Goal:\*\* Support larger teams and higher transaction volumes.

| Task | Priority | Effort | Notes |
